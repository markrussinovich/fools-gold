# Public dataset tooling

`bash scripts/data/download_public.sh [dest_root]` fetches every public
benchmark the pipeline uses, converts the ones the pipeline consumes in a
derived form, and verifies row counts/schemas. It is idempotent (verified
files are skipped; the verification pass always runs). `dest_root` (default
`data/public`, git-ignored) holds raw Hugging Face inspection copies only —
the files the pipeline actually reads are always materialized at their
repo-anchored paths, because every consumer script resolves them relative to
the repo root.

Helper scripts (invoked automatically, runnable standalone):

| Script | Produces | Notes |
|---|---|---|
| `convert_fortress.py` | `data/eval/fortress_cbrne_eval.jsonl` | 180-row CBRNE slice of `ScaleAI/fortress_public` (500 rows); filter + field mapping ported verbatim from the study's original pool-assembly script (private campaign repo `scripts/archive/cbrn_c0_pool.py`), so the output is byte-identical to the paper's eval file. Eval-only per the dataset card. |
| `make_splits.py` | `data/eval/harmless_dev.jsonl`, `data/archive/abliteration/*.jsonl`, `data/archive/eval/*.jsonl`, `data/train/harmless_direction.jsonl`, `data/manifest.json` | Calls `src/antiablit/data.py::prepare()` with the registered constants (seed 17; AdvBench 128/64/200 cut; Alpaca no-input rows, n=1024) — reproduces the frozen splits byte-identically. AdvBench rows come from the local `data/archive/advbench_train.csv` (the gated `walledai/AdvBench` hub mirror is only a fallback when no CSV exists): same 520 goals, same row order — verified — so no HF credentials are needed. |

## Resolved from the Hugging Face cache at run time (warmed by this script)

The pipeline runs **hub-offline by design** — every `line*.sh` stage exports
`HF_HUB_OFFLINE=1` — so nothing fetches itself at run time. These consumers
resolve their datasets from the local HF cache (`$HF_HOME`), which
`download_public.sh` populates as a side effect of its pinned fetches; run it
(with the same `HF_HOME` the pipeline will use) before any pipeline stage.
Model weights are likewise pre-fetched, not run-time-fetched — see
`docs/REPRODUCING.md` Requirements.

## Flags / known gaps (for repo maintainers)

1. **`data/archive/cbrn/pool_screened.jsonl` is not reconstructible from
   public sources.** It is the 601-prompt screened pool (SOSBench +
   HarmBench text — both fetched here — plus campaign-assigned `axis` /
   `operational` labels and refusal counts). `line_b0_screen.py` requires it,
   `/data/` is git-ignored, and no labeling script ships — either ship the
   file (prompts are public benchmark text) or port the archived labeling
   chain.
2. **`src/antiablit/data.py::prepare()` still fetches two unpinned sources
   internally**: `tatsu-lab/alpaca` without a `revision=`, plus the HarmBench
   CSV from the repo's `main` branch for `harmbench_standard.jsonl`. (The
   AdvBench side is resolved: prepare()'s csv seam reads the commit-pinned
   local `data/archive/advbench_train.csv`, hub order verified — the gated
   `walledai/AdvBench` mirror is only a fallback when no CSV exists.) The
   consumed outputs (`harmless_dev.jsonl`, `harmful_direction.jsonl`,
   `harmless_direction.jsonl`) are protected by byte-identity sha256 asserts
   in `make_splits.py` and the download script's verification pass, so any
   upstream revision fails loudly; `harmbench_standard.jsonl` has no shipped
   consumer and is left unpinned. When `data.py` is next synced, consider a
   `revision` cfg seam for Alpaca and reading the already-pinned local
   `data/eval/harmbench_behaviors_text_all.csv` instead of refetching.
3. `convert_fortress.py` provenance: ported from the private repo's
   `scripts/archive/cbrn_c0_pool.py` (FORTRESS section). If that script
   changes, re-port.
